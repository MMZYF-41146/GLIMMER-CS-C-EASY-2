# GLIMMER-CS-C-EASY-2

## Step 1.指针与结构体

### 一、什么是指针？
**定义**：指针是一种特殊变量，用来存内存地址。
**我的理解**：如果把内存比作一排排的房间（每个房间有门牌号），普通变量是住在房间里的"人"，而指针就是写着"门牌号"的小纸条。只要有了纸条，就能找到那个房间。
C 语言里有两个关键符号：
-   **`&` (取地址)**：获取变量的门牌号。
-   **`*` (解引用)**：根据门牌号找到房间里的人（或者修改里面的人）。
1. **怎么定义？**
格式是 `类型 *变量名;`。比如 `int *p;` 就是定义了一个专门存 `int` 类型地址的指针。
   **大小固定吗？**
**不固定！** 这一点我一开始搞错了。指针的大小跟它指向的数据类型没关系，而是跟**操作系统位数**有关：
    -   **32位系统**：地址是32位的，所以指针占 **4字节**。
    -   **64位系统**：地址是64位的，所以指针占 **8字节**。
2. **代码输出结果及原因**
结果：x=20 y=10
原因：*p = 20;这一步通过指针把 x 改成了 20
      *arr 就是 arr[0]，值是 3；++ 是前缀自增，所以 arr[0] 先变成 4，整个表达式的值也是 4
      ++q是指指针 q 往后挪一位，现在指向 arr[1]（也就是 6）；*取出 q 指向的值，就是 6
      所以y=4+6=10
3. **什么是野指针？**
就是一个"乱指"的指针，不知道它指向哪里，或者指向了一块已经不能用的内存。
   **危害**
可能会导致程序崩溃（野指针指向的地址可能是非法的）；
数据被悄悄改坏（可能会覆盖别人的数据）；
可能会有安全漏洞（黑客利用其搞破坏）。
   **如何避免**
int *p = NULL;   // 定义时就初始化，null是空指针（不指向任何有效的内存地址
free(p);         //把这块内存还给系统
p = NULL;        // 释放后立刻置空

### 二、什么是结构体？
**定义**：用户自定义的复合数据类型，可包含不同数据类型的成员。
**我的理解**：数组只能存同一类型的数据（比如全装 int），而结构体像一个"快递盒"，可以把不同类型的数据打包在一起。
1. 代码已上传至仓库（typedef 的作用：给类型起个新名字。就像给 struct {...} 这整个类型取了个外号叫 PerInfo。）
2. **结构体指针的含义**
就是指向结构体变量的指针，存的是结构体的地址。**用指针访问结构体成员时，不用点 . 而用箭头 ->。**
3. **内存对齐规则**（代码已上传至仓库）
第一个成员放在偏移量为 0 的地址处；
其他成员要对齐到自己类型大小的整数倍地址处；
结构体总大小必须是最大成员大小的整数倍。

### 三、学习思考
我在学习指针的时候用**`&`**和**`*`**分别做了实验，用实践更加理解了发*与&的区别，*的输出结果是数字而&的输出结果是一个十六进制的地址。

## Step2.链操作
**定义**：链表是一种线性数据结构，它由一组节点组成，每个节点包含数据域和指针域；数据域用于存储元素本身，指针域用于存储下一个节点的地址，从而把各个节点按逻辑顺序连接起来。

### 一、 链表和数组的区别：到底差在哪？
- **数组**：就像一排**连号的储物柜**。
  - **优点**：找东西快，比如我要找第3个柜子，直接走过去打开就行（这叫随机访问）。
  - **缺点**：太死板，如果我想在第1个和第2个柜子中间硬塞一个新柜子进去，就得把后面所有的柜子都往后挪一位，太麻烦了（插入/删除慢）。而且一开始就得定好买多少个柜子，买少了不够用，买多了浪费。
- **链表**：就像一场**寻宝游戏**。
  - **特点**：每个宝箱（节点）里除了宝物（数据），还有一张纸条（指针），写着下一个宝箱在哪。宝箱在地图上可以是散乱分布的。
  - **优点**：灵活，我想加个宝箱，只要把前一个宝箱的纸条改一下指向新宝箱就行，不用挪动其他宝箱（插入/删除方便）。而且想要多少个就造多少个。
  - **缺点**：找东西慢，如果我要找第10个宝箱，我必须从第1个开始，顺着纸条一个一个找过去，不能直接跳过去（不支持随机访问）。

### 二、 单向链表长什么样？（节点定义）
单向链表就是由一个个“节点”串起来的。
每个节点其实就是一个结构体，里面必须有两样东西：
   **数据域 (`data`)**：用来存我们要的数据（题目要求是整数 `int`）。
   **指针域 (`next`)**：用来存下一个节点的地址。

### 四、我踩过的雷 
1. **段错误**
   - **原因**：访问了 `NULL` 的 `next` 或者 `data`。
   - **对策**：在使用任何指针前，永远先问自己一句：“它可能是空的吗？” 特别是在遍历循环的终止条件里。
2. **内存泄漏**
   - **原因**：`malloc` 了节点，删的时候只改了指针，忘了 `free`。
   - **对策**：删除节点的标准动作是“改指针 -> free节点”，这两个动作必须绑定在一起。
3. **头指针丢失**
   - **原因**：在函数里修改了 `head`，但函数结束后外面的 `head` 没变。
   - **对策**：如果要改变头指针本身（比如头插、删除头节点、反转），函数参数必须传**二级指针** (`Node **head`) 或者**返回新的头指针**。
